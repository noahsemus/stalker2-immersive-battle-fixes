# Building ImmersiveBattleFixes (Zone Kit pak)

For anyone who wants to rebuild, modify or extend the mod: what it changes, exactly how, and how to cook it.
Toolchain, cook rules and traps shared by all our mods are in [harness/docs/pipeline.md](harness/docs/pipeline.md)
and [harness/docs/blueprints.md](harness/docs/blueprints.md).

## 1. Prerequisites
- S.T.A.L.K.E.R. 2 Zone Kit (Epic Games Store), ~600 GB free. First launch compiles shaders for a long time.
- Git. No Python install needed (the kit ships 3.11).
- Run `harness\tools\setup.ps1` once: it finds your Zone Kit and game and stores them outside the repo.

## 2. What the mod is
A Zone Kit plain-mod plugin `ImmersiveBattleFixes`.

| File (under `Content/`) | Kind | Container | What it does |
|---|---|---|---|
| `GameLite/GameData/**/*_patch_ImmersiveBattleFixes.cfg` (108 files) | cfg patches (loose files) | OverrideContent | Every fight change: spawn actor patches (squad member lists, DamageMultiplier, respawn fields), quest node patches (relaunched / added nodes, MCM switches), our global variables, the MCM setter nodes in `rootgraph`. All written by `zonekit/tools/gen_patches.py` from its `BATTLES` data |
| `Runtime/BP_ImmBFSubsystem` | Blueprint (ModWorldSubsystem) | NewContent | Spawns the MCM provider by soft class path when MCM is installed (`gen_mcm.py` paste) |
| `Runtime/BP_ImmBFMCM` | Blueprint (Actor, implements `/ModConfigurationMenu/BPI_MCM_SettingsProvider`) | NewContent | The 17 MCM settings; on Apply starts the setter quest node of each value (`CppMediator.StartQuestNode` + console twin). Variables and the 41 `Sid_*` PrototypeSID defaults from `setup_assets.py` |
| `Runtime/T_ImmBF_MCMHeader`, `T_ImmBF_MCMCatHeader` | Textures | NewContent | MCM header pictures (copies of MCM_ModExample1's, as ImmersiveLooting) |
| `Autogenerated_*_WorldSubsystemData` | Package Mod output | OverrideContent | Makes the game create the subsystem |

## 3. Build from the committed source
1. `powershell -File harness\tools\deploy_to_kit.ps1` (plugin + classifier lists into the kit).
2. Start the editor once and pick `ImmersiveBattleFixes` in the toolbar mod selector (mounts the plugin).
3. `powershell -File harness\tools\cook_and_install.ps1` (cook, then install as `~mods\zzz_ImmersiveBattleFixes_PakTest\`).
Release zips ship the override container as `zzz_ImmersiveBattleFixes_20_P.*` and the NewContent container under the kit name.

## 4. The edits, asset by asset
1. cfg patches: `python -I zonekit/tools/gen_patches.py` (kit Python) writes all of them into the kit plugin
   (`--dry` prints them; it validates every GUID / node against vanilla first) and `zonekit/tools/mcm_settings.json`.
   What each fight changes and why: the comments in `BATTLES` and `PLAN.md`.
2. Blueprints: `ue_exec.py zonekit/tools/setup_assets.py` (creates both Blueprints, their variables and defaults, the
   header textures); add the interface `BPI_MCM_SettingsProvider` to `BP_ImmBFMCM` by hand (Class Settings >
   Interfaces); `python -I zonekit/tools/gen_mcm.py <BP_MCM_ModExample1.t3d> zonekit/paste` and paste
   `zonekit/paste/<BP>/EventGraph.txt` into each Event Graph (Ctrl+A, Delete, Ctrl+V, Refresh All Nodes, Compile,
   Save); press Package Mod once. The `.uplugin` lists ModConfigurationMenu as an optional plugin.

## 5. Traps specific to this mod
- The MCM setter SIDs come from `Sid_*` variables: a literal PrototypeSID pin default came through empty on paste.
- Lifted MCM node names must be unique (`gen_mcm.py` asserts it): duplicates were dropped and the mod vanished from
  the menu.
- Battle changes only reach a save from before the fight starts (new nodes hang off launchers that already ran).
